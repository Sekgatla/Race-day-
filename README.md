# 🏃 RaceDay Event Management System\n\n[![Part 1 Documentation Check](https://github.com/Sekgatla/Race-day-/actions/workflows/part1-ci.yml/badge.svg)](https://github.com/Sekgatla/Race-day-/actions/workflows/part1-ci.yml)\n\n> A planned event management platform for South African running, walking and cycling events.\n\nRaceDay is designed to replace paper registrations, separate spreadsheets and manual result tracking with one organised system for event organisers and participants. Part 1 establishes the database and API blueprint that will support the application in Parts 2 and 3.\n\n## 👥 User Roles\n\n| Role | Main responsibilities |\n| --- | --- |\n| **Organiser** | Create, update and delete events; manage categories; view enrolments; capture results; maintain route and weather information. |\n| **Participant** | Create an account; browse events; choose a category; enrol; view enrolments; track personal results and performance history. |\n\nRole-based access will be enforced by the API in Part 2 and reflected in the MVC interface in Part 3.\n\n## 📚 Part 1 Deliverables\n\n| Document | Description |\n| --- | --- |\n| [RaceDay ERD](docs/RaceDay_ERD.pdf) | Seven-entity relational database design with keys, relationships and cardinality. |\n| [Editable ERD source](docs/RaceDay_ERD.dot) | Graphviz source for the ERD. |\n| [API Endpoint Plan](docs/RaceDay_API_Endpoint_Plan.md) | Planned REST endpoints, request bodies, roles and responses. |\n| [SQL Database Script](docs/RaceDay_Database.sql) | SQL Server schema, constraints, realistic seed data and verification queries. |\n\nThe seven entities are **Users, Events, Categories, Enrolments, Results, Routes and EventWeather**. Enrolments resolves the many-to-many relationship between participants and events while recording the selected category.\n\n## 🗄️ Database Setup\n\nThe database script is written for Microsoft SQL Server and is intended to be run in SQL Server Management Studio (SSMS).\n\n1. Open `docs/RaceDay_Database.sql` in SSMS.\n2. Execute the complete script from top to bottom on a clean SQL Server instance.\n3. Confirm that the `RaceDayDb` database and all seven tables are created.\n4. Review the verification queries at the end of the script.\n5. Confirm the organiser, participant, event, category, enrolment, route, weather and result sample data.\n\nThe script defines primary keys, foreign keys, `NOT NULL`, `UNIQUE`, `DEFAULT` and `CHECK` constraints.\n\n## 🔌 API Planning\n\nThe endpoint plan contains authentication, user profile, event, category, enrolment and result endpoints. It also includes route and weather endpoints to support the wider RaceDay requirements.\n\nEach endpoint documents the HTTP method, route, description, required role, request body and expected response. Organiser-only actions are separated from Participant actions so that access rules can be implemented consistently in Part 2.\n\n## ✅ GitHub Actions / CI\n\nThe workflow in [.github/workflows/part1-ci.yml](.github/workflows/part1-ci.yml) checks that the `docs` folder exists and that the ERD, API endpoint plan, SQL script and README are present and non-empty.\n\nThe latest documentation check completed successfully:\n\n![Successful Part 1 CI build](docs/ci-green-build.png)\n\n## 🎥 Video Demonstration\n\nThe Part 1 video uses my own voiceover to demonstrate the repository, ERD decisions, API endpoint plan, SQL design, live SSMS execution, seeded data and the successful GitHub Actions build.\n\n**Unlisted YouTube link:** _Add the final unlisted YouTube URL here before submission._\n\n## 📁 Repository Structure\n\n```text\nRace-day-/\n├── README.md\n├── docs/\n│   ├── RaceDay_ERD.pdf\n│   ├── RaceDay_ERD.dot\n│   ├── RaceDay_API_Endpoint_Plan.md\n│   ├── RaceDay_Database.sql\n│   └── ci-green-build.png\n└── .github/\n    └── workflows/\n        └── part1-ci.yml\n```\n\n## 🚀 Next Parts\n\nParts 2 and 3 will build on this blueprint by implementing the RESTful API, connecting it to the database, adding unit tests, creating the MVC application, integrating Azure Blob Storage and containerising the final application.\n
