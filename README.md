<div align="center">\n\n# RaceDay\n\n**Event management and race results platform**\n\nA planning blueprint for South African running, walking and cycling events.\n\n[![Part 1 Documentation Check](https://github.com/Sekgatla/Race-day-/actions/workflows/part1-ci.yml/badge.svg)](https://github.com/Sekgatla/Race-day-/actions/workflows/part1-ci.yml)\n\n</div>\n\n---\n\n### Overview\n\nRaceDay is designed to replace paper registrations, separate spreadsheets and manual result tracking with one organised system for organisers and participants. This repository contains the Part 1 database and API planning work that will guide Parts 2 and 3.\n\n### User roles\n\n| Role | Responsibilities |\n|:---|:---|\n| **Organiser** | Manage events and categories, view enrolments, capture results, and maintain route and weather information. |\n| **Participant** | Create an account, browse events, choose a category, enrol, and view personal results. |\n\n### Part 1 evidence\n\n| File | Purpose |\n|:---|:---|\n| [ERD](docs/RaceDay_ERD.pdf) | Seven-entity data model with keys, relationships and cardinality. |\n| [ERD source](docs/RaceDay_ERD.dot) | Editable Graphviz source. |\n| [API endpoint plan](docs/RaceDay_API_Endpoint_Plan.md) | Methods, routes, roles, request bodies and responses. |\n| [SQL database script](docs/RaceDay_Database.sql) | SQL Server schema, constraints, seed data and verification queries. |\n\nThe data model contains **Users, Events, Categories, Enrolments, Results, Routes and EventWeather**. Enrolments connects participants to events and records the selected category.\n\n### Database setup\n\nRun `docs/RaceDay_Database.sql` in SQL Server Management Studio (SSMS) on a clean SQL Server instance. Execute it from top to bottom, then use the verification queries at the end to review the tables and sample records.\n\nThe script includes primary keys, foreign keys, `NOT NULL`, `UNIQUE`, `DEFAULT` and `CHECK` constraints.\n\n### API plan\n\nThe planned REST API covers authentication, user profiles, events, categories, enrolments and results, with additional route and weather endpoints. Organiser and Participant access rules are documented for each endpoint.\n\n### CI evidence\n\nThe workflow in [.github/workflows/part1-ci.yml](.github/workflows/part1-ci.yml) checks that the required documentation folder and files exist and are non-empty.\n\n<p align="center">\n  <img src="docs/ci-green-build.png" alt="Successful Part 1 GitHub Actions build" width="480">\n</p>\n\n### Video presentation\n\nThe presentation explains the repository, ERD decisions, API plan, SQL design, live SSMS execution, sample data and the successful CI build.\n\n> **Unlisted YouTube link:** _Add the final unlisted video URL here before submission._\n\n### Repository layout\n\n```text\nRace-day-/\n├── README.md\n├── docs/\n│   ├── RaceDay_ERD.pdf\n│   ├── RaceDay_ERD.dot\n│   ├── RaceDay_API_Endpoint_Plan.md\n│   ├── RaceDay_Database.sql\n│   └── ci-green-build.png\n└── .github/workflows/part1-ci.yml\n```\n\n### Roadmap\n\n- **Part 1:** System planning and database design\n- **Part 2:** RESTful API, database connection and unit tests\n- **Part 3:** MVC application, Azure Blob Storage and containerisation\n
