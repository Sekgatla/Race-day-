# RaceDay Event Management System\n\nRaceDay is a planned event management system for South African running, walking, and cycling events. It is designed to replace paper registrations, separate spreadsheets, and manual result tracking with one organised platform for event organisers and participants.\n\n## User Roles\n\n### Organiser\n\nOrganisers will be able to create, update, and delete events; manage event categories; view enrolments for their events; capture participant results; and maintain route and weather information.\n\n### Participant\n\nParticipants will be able to create an account, log in, browse available events, choose a category, enrol in an event, view their own enrolments, and track their personal results and performance history.\n\nRole-based access will be enforced by the API in Part 2 and reflected consistently in the MVC interface in Part 3.\n\n## Part 1 Deliverables\n\nThis repository contains the RaceDay Part 1 planning and database work:\n\n- [`docs/RaceDay_ERD.pdf`](docs/RaceDay_ERD.pdf) — the seven-entity relational database design.\n- [`docs/RaceDay_ERD.dot`](docs/RaceDay_ERD.dot) — editable Graphviz source for the ERD.\n- [`docs/RaceDay_API_Endpoint_Plan.md`](docs/RaceDay_API_Endpoint_Plan.md) — planned REST API endpoints, request bodies, roles, and responses.\n- [`docs/RaceDay_Database.sql`](docs/RaceDay_Database.sql) — SQL Server schema, constraints, seed data, and verification queries.\n\nThe seven entities are Users, Events, Categories, Enrolments, Results, Routes, and EventWeather. Enrolments resolves the many-to-many relationship between participants and events while also recording the selected category.\n\n## Database Setup\n\nThe database script is written for Microsoft SQL Server and can be opened in SQL Server Management Studio (SSMS).\n\n1.
